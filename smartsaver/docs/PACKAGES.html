Zustand vanilla store: stops (index 0 is the origin), optimize, roundTrip (both default on), route, estimate, status, error, list. Actions toggleItem (persists the list), setOrigin, addStop (dedupes, max 25), removeStop, moveStop, reorderStop, setOptimize, setRoundTrip, computeRoute. Every stop change recomputes the route; a superseded request is aborted and its result dropped

deals({ postalCode, q? }, signal?)

src/deals.ts

/api/deals client. Returns Result; keeps at most 100 rows and drops rows without a string id/name/merchant, a finite price (and wasPrice if present), or a 3-letter currency code

apps/web

React 18 + Vite 5 SPA. Vite dev server proxies /api to localhost:8787. Zustand (via packages/core) holds trip state; Vitest is installed but has no web tests yet. Build steps 1–7 of SmartSaver — Web App Build Plan (apps/web) are implemented: a 404px side panel (bottom sheet below 860px) beside a MapLibre map on OpenFreeMap tiles. The panel has “Use my location”, a place search (Nominatim, debounced 400 ms, 3+ characters) that adds stops, a stop list (up/down buttons or drag to reorder, remove; the first stop is the origin, shown as A and kept first), a route summary (distance, time, fuel, with round-trip and optimize toggles), an “Open in Google Maps” button (Apple Maps and Waze as secondary) that hands off the stops in optimized order, a collapsible “My Staples” grocery list (tap items to mark them needed), and a postal-code/query search that calls GET /api/deals (through the core deals client) and lists the results. Each deal has an “Add stop” button: deals carry only a merchant name, so the app asks /api/stores for grocers near the origin (or near the searched postal code, resolved with postalPlace, when there is no origin) and adds the nearest one whose name matches the merchant. If none match, it falls back to geocoding the merchant name within ~30 km. Above the deals, “On sale from your list” shows each needed item found in the loaded deals with its cheapest deal, and counts the misses (“2 of 3”). If nothing matches, the card says so and points to the stop search. The map shows a marker per stop, the route polyline, and fits its view to the stops (Toronto until the first stop). The tile style is set by VITE_MAP_STYLE_URL (see .env.example). vite.config.ts excludes maplibre-gl from dependency pre-bundling so its worker loads in dev. Screens: User States.
