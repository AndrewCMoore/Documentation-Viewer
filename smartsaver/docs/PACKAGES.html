Zustand vanilla store: stops (index 0 is the origin), optimize, roundTrip (both default on), route, estimate, status, error, list. Actions toggleItem (persists the list), setOrigin, addStop (dedupes, max 25), removeStop, moveStop, reorderStop, setOptimize, setRoundTrip, computeRoute. Every stop change recomputes the route; a superseded request is aborted and its result dropped

/api/deals client. Returns Result; keeps at most 100 rows and drops rows without a string id/name/merchant, a finite price (and wasPrice if present), or a 3-letter currency code

Seeded “My Staples” list (11 categories, ~65 items, each with matchTerms, none needed by default), persisted under smartsaver.list.v2; corrupted storage reseeds. Map of item id to matching deals, cheapest first. Keyword match with plural, diacritic, descriptor and store-brand normalization; rejects derived products (“chicken broth” is not chicken) unless asked for

apps/web

React 18 + Vite 5 SPA, restyled to the original smartsaver (v1) look and feel — tokens, layout and component markup from SmartSaver — Style Guide (Addendum to ARCHITECTURE.md) — while keeping this app’s own data flow (API-backed deals, nearby/findStore stop resolution, PlaceSearch, ListMatches). Vite dev server proxies /api to localhost:8787. Zustand (via packages/core’s tripStore) holds trip state; Vitest + Testing Library cover the ported v1-only components. Build steps 1–8 of SmartSaver — Web App Build Plan (apps/web) are implemented: a 404px side panel (bottom sheet below 860px) beside a MapLibre map on OpenFreeMap tiles. The panel has “Use my location”, a place search (Nominatim, debounced 400 ms, 3+ characters) that adds stops, a stop list (up/down buttons or drag to reorder, remove; the first stop is the origin, shown as A and kept first), a route summary (distance, time, fuel, with round-trip and optimize toggles) with an inline cost-model panel underneath it, an “Open in Google Maps” button (Apple Maps and Waze as secondary) that hands off the stops in optimized order, a compact “My Staples” summary that opens the full grocery list editor (SmartSaver — Grocery List Editor UI (Addendum to GROCERY_LIST.md): shop/edit modes, categories, add/rename/reorder/delete, undo), and a postal-code/query search that calls GET /api/deals (through the core deals client) and lists the results. Each deal has an “Add stop” button: deals carry only a merchant name, so the app asks /api/stores for grocers near the origin (or near the searched postal code, resolved with postalPlace, when there is no origin) and adds the nearest one whose name matches the merchant. If none match, it falls back to geocoding the merchant name within ~30 km. A successful deals search also feeds the trip store’s deals/candidates (via the same nearby lookup), which drives the Worth-It card (SmartSaver — Worth-It Engine (Addendum to ARCHITECTURE.md)): itemized savings, detour and fuel cost per candidate store, a net-benefit verdict, an estimated grocery bill, and grocer pins/popup plus a “Saving $x” chip on the map. Above the deals, “On sale from your list” shows each needed item found in the loaded deals with its cheapest deal, and counts the misses (“2 of 3”). If nothing matches, the card says so and points to the stop search. The map shows a marker per stop and per nearby grocer, the route polyline, and fits its view to the stops (Toronto until the first stop). The tile style is set by VITE_MAP_STYLE_URL (see .env.example). vite.config.ts excludes maplibre-gl from dependency pre-bundling so its worker loads in dev. Screens: User States.
