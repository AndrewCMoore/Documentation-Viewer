SmartSaver — Style Guide (Addendum to ARCHITECTURE.md)

Planning document. No application code yet — this captures the visual design system so we build against one consistent look. Read alongside ARCHITECTURE.md (layout: panel + map), DEALS.md, GROCERY_LIST.md, and WORTH_IT.md. Canonical tokens live in style-guide/tokens.mjs (platform-neutral data, consumed directly by React Native); style-guide/tokens.css is generated from it via node style-guide/build-tokens.mjs. A living, toggleable reference is style-guide/style-guide.html.

1. Design intent — the four-brand synthesis

SmartSaver borrows a specific strength from each reference rather than copying one wholesale. The blend is deliberate; when they conflict, the rule in the last column wins.

From

What we take

Where it shows up

Airbnb

Warmth, rounded forms, soft shadows, card-driven layout, generous whitespace

Deal cards, the Worth-It card, overall friendliness

Lattice

Calm, professional data density; color used sparingly

The panel: stop list, breakdowns, summaries

Revolut

Precise, confident treatment of money; strong dark mode

Savings figures, net-benefit total, tabular numerics

Slack

A distinctive accent + clear information architecture

Indigo brand color, section rhythm, primary actions

One-line personality: warm and human, but precise about money. Friendly enough to enjoy, trustworthy enough to act on a dollar figure.

2. Core color decisions (locked)

Two decisions drive the whole palette:

  1. Brand accent = indigo/violet. Brand mark, primary buttons, links, route line, map pins, stop numbers, focus rings. Distinctive (Slack-aubergine meets Revolut-violet) and, crucially, not green — so it never competes with money.

  2. Money = green, always and only. Savings amounts, sale prices, and the “Worth it ✓” verdict are green everywhere. Green is reserved for positive money; it is never a brand or decorative color. This is what lets a user scan the screen and trust that “green = you saved.”

Everything else is warm-neutral so those two signals stand out.

3. Theme posture

Light-first, dark-ready. Light is primary (matches Airbnb / Lattice / Slack); dark is fully specified via token pairs (Revolut-grade), not an afterthought. Every color token below has a light and a dark value. Components must reference tokens only — never hard-coded hex — so a theme swap is free.

The dark theme applies via prefers-color-scheme and can be forced with a data-theme="light|dark" attribute on the root (user override wins).

4. Color tokens

Hex pairs are the source of truth (defined in tokens.mjs, generated into tokens.css). “AA” = meets WCAG 2.1 contrast ≥ 4.5:1 as body text on the adjacent surface; “AA-large / non-text” = use only for ≥ 19px bold text, icons, borders, or fills.

4.4 Map surface (non-UI, illustrative)

The MapLibre canvas isn’t themed by these tokens (tiles come from OSM), but our overlays are: route line = --brand, with a white/--surface casing beneath for legibility on any tile; markers use --brand fill + --on-brand text; the origin pin uses --text. The floating savings chip uses --surface + --money.

5. Typography

Font: Inter (brand face, decided — §14), with the system stack as fallback until it loads. Chosen over the alternatives (Geist, staying on the system stack) because Inter ships proven tabular figures on every platform — the trust anchor for money, since the system default doesn’t guarantee them on Android (§15) — and is optimised for the 12–17px UI sizes that dominate the panel.

--font-sans: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
             "Helvetica Neue", Arial, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;

Inter must be bundled/self-hosted — web via @font-face, native via the app’s font assets (family name Inter) — not pulled from a CDN at runtime. Ship the same weights used below (400–800). Swap the face later by changing fontFamily.sans in tokens.mjs (→ --font-sans) only.

Weights used: 400 / 500 / 600 / 700 / 800 (avoid in-between weights so non-variable fallbacks render identically).

7. Component specs

Reference render: style-guide/style-guide.html. Each component references tokens only.

Button — primary. Fill --brand, text --on-brand, --radius-sm, padding 14px, weight 700, --shadow-sm. Hover → --brand-strong. Full-width for the main action (“Open in Google Maps”). One primary per view.

Button — secondary / ghost. --surface fill, 1px --border-strong, text --text. Hover → --surface-2. Used for the nav-app alternates (Apple, Waze).

“Add stop” chip. Transparent fill, 1px --brand, text --brand-text, --radius-pill. Hover → --brand-weak. A deliberately light-weight action so it doesn’t outshout the primary CTA.

Input / search. --surface-2 fill, 1px --border, --radius-sm, leading icon in --text-3. Focus → 2px --brand border + focus ring (see §8).

Card (generic + deal). --surface, 1px --border, --radius-md, --shadow-sm; hover lifts to --shadow-md + translateY(-1px). Deal card = 64px image tile (--radius-sm) + title (body, 600) + merchant (caption, --text-2) + price row (sale in --money 700 tabular, was-price struck in --text-3) + trailing “Add stop” chip.

Worth-It card (hero). The most emphasised surface: --radius-md, --shadow-md, subtle surface→surface-2 gradient. Header = store + “vs. your usual store” counterfactual (WORTH_IT.md §10) + “Worth it ✓” badge. Itemised rows (savings + green, detour neutral, fuel − cost-amber) above a dashed divider, then the net-benefit total oversized in --money. Always show the arithmetic — never a bare verdict.

Badge / pill. --radius-pill, caption+ weight 700. “Worth it” = --money-weak bg / --money text; “Skip” = --danger-weak / --danger.

Stat / summary row. Horizontal group (Distance · Time · Fuel) in --surface-2; value 15/700 tabular, label overline in --text-3.

Stop row + pins. 24px circular pin; origin = --text fill / white; numbered stops = --brand-weak bg / --brand-text. Row hover → --surface-2; trailing drag grip in --border-strong.

Icons. Set = Lucide (lucide-react web, lucide-react-native native — same glyphs, satisfies §15). Chosen because its defaults are this system’s existing convention: 2px stroke, round caps/joins, 24×24 grid — so no per-icon overrides. ISC-licensed; maintained superset of Feather. Glyph 24px default, 20px in dense rows (stat row, chips); the interactive hit target stays 40/44px (§8), not the glyph box. Color via currentColor — inherit from the parent’s text token (--text-2/--text-3 for affordances, --brand-text on-surface, --on-brand on fills); status glyphs use --money/--danger/cost-amber to match their labels. Never hard-code a hex, never mix in a second icon set.

8. Focus, states, accessibility

  • Focus ring (keyboard): 0 0 0 3px of --brand at ~35% alpha, on top of a solid --brand border. Never remove focus outlines; style them. --focus-ring: 0 0 0 3px rgba(90,80,225,.35) (light) / rgba(139,129,231,.45) (dark).

  • Contrast: body text meets AA (≥4.5:1); --text-3 is for placeholder / non-text only. Don’t put --money small text on --money-weak without checking.

  • Color is never the only signal. “Worth it ✓” / “Skip ✕” pair color with a glyph and a word; deltas carry + / − signs. Col-blind-safe by construction.

  • Hit targets ≥ 40px on touch (mobile / bottom-sheet mode).

  • Reduced motion: honor prefers-reduced-motion — drop transforms/animation, keep instantaneous state changes.

9. Motion

Purposeful and quick; nothing bounces.

--dur-fast:120ms  --dur:160ms  --dur-slow:240ms
--ease: cubic-bezier(.2,.7,.3,1)   /* ease-out, confident settle */

Hover lifts (cards) and color transitions use --dur/--ease. Route drawing and bottom-sheet transitions use --dur-slow. Respect §8 reduced-motion.

10. Responsive (ties to ARCHITECTURE.md §3)

Sidebar-and-map on desktop → panel becomes a bottom sheet on mobile, per the architecture. Breakpoints:

--bp-sm:640   --bp-md:860 (panel ↔ bottom sheet)   --bp-lg:1080

Panel fixed ~404px on desktop; map fills the rest. Below --bp-md, map goes full-bleed and the panel docks as a draggable bottom sheet over it.

11. Using the tokens (integration)

Framework-agnostic by design (mirrors the lib/ philosophy). The canonical source is style-guide/tokens.mjs — platform-neutral data (colors as light/dark pairs, dimensions as unitless numbers, platform-specific constructs like shadows/fonts/easing carried per-platform). tokens.css is generated from it; never hand-edit the CSS.

Regenerate CSS: node style-guide/build-tokens.mjs (add --check in CI to fail the build if tokens.css is stale).

Web — plain CSS / any framework — import the generated style-guide/tokens.css, then reference var(--…). Theme by setting data-theme on <html> (or let prefers-color-scheme decide).

App — React Native — import tokens.mjs directly (no CSS, no var()): read color.<group>.<name>[theme], unitless space/radius/type into StyleSheet, and the per-platform elevation/fontFamily/easing fields. Theme via useColorScheme(); breakpoints via useWindowDimensions() against breakpoint. Web-only tokens (focusRing) are ignored on native. See the header of tokens.mjs for the cross-platform caveats (multi-layer shadows, tabular-nums on Android).

Tailwind (if we adopt it) — map the CSS vars in tailwind.config.js so utilities resolve to tokens and inherit theming automatically:

// tailwind.config.js — theme.extend
colors: {
  brand:   { DEFAULT:'var(--brand)', strong:'var(--brand-strong)',
             weak:'var(--brand-weak)', text:'var(--brand-text)' },
  money:   { DEFAULT:'var(--money)', strong:'var(--money-strong)', weak:'var(--money-weak)' },
  cost:'var(--cost)', danger:'var(--danger)',
  canvas:'var(--canvas)', surface:'var(--surface)', 'surface-2':'var(--surface-2)',
  border:'var(--border)', text:{ DEFAULT:'var(--text)', 2:'var(--text-2)', 3:'var(--text-3)' },
},
borderRadius:{ xs:'8px', sm:'11px', md:'16px', lg:'20px' },
boxShadow:{ sm:'var(--shadow-sm)', md:'var(--shadow-md)', lg:'var(--shadow-lg)' },

14. Open follow-ups (not yet decided)

  • Brand typeface — decided: Inter (§5). Adopted over Geist and the system stack for proven cross-platform tabular figures (the §15 Android risk) and small-size UI legibility. Still to do: bundle/self-host the weights.

  • Logo/mark — the current route-glyph in a rounded indigo tile is a placeholder, not a finalised logo. Candidate marks are drafted in style-guide/logo-options.html (route-S monogram recommended); pick one to close this.

  • Empty / error / loading states — defined: §16. Layout, timing, tokens, and copy tone are locked. Still deferred: the bespoke illustration art for zero-states (§16.2 uses a stroke-icon placeholder until then).

15. Cross-platform notes (web ↔ React Native)

Per ARCHITECTURE.md §2 (web now, React Native later), the token values are platform-neutral, but several mechanisms in this guide are web-only. tokens.mjs is the shared source (§11); this section is the porting contract for everything CSS can express that RN cannot. Rule of thumb: anything that is a value (color, size, weight, duration) ports 1:1; anything that is a CSS feature (cascade, var(), @media, box-shadow, :focus, :hover, gradients) needs a native equivalent below.

Elevation is an approximation on native. Our soft, diffuse look (§6) uses two stacked shadow layers — CSS only. iOS accepts a single shadow* set (the ios field in elevation), and Android reduces the whole thing to one elevation integer with no color or spread control. Treat the native values as a faithful impression of the web card, not a pixel match; don’t try to recreate the double-layer softness natively.

tabular-nums on Android — resolved by bundling Inter. “Green = you saved” is the trust anchor of the product, and misaligned figures undercut it. iOS renders tabular figures reliably; on Android it only works if the shipped font provides them, and the platform default does not guarantee it. This drove the §14 brand-typeface decision: we ship Inter (proven tabular figures) rather than relying on the platform default, so the risk is closed on both platforms — as long as the face is actually bundled (§5), not left to a fallback.

Press replaces hover — and needs specifying. The guide leans on :hover (cards lift to --shadow-md + translateY(-1px); buttons go to --brand-strong), none of which fires on touch. Define the pressed state as the primary interactive feedback on both platforms (it’s currently a spec hole even for mobile web):

  • Primary button — pressed: fill --brand-strong, no lift.

  • Secondary / ghost — pressed: fill --surface-3.

  • Card / stop row — pressed: fill --surface-2, no translateY on touch (reserve the lift for hover-capable pointers via @media (hover: hover) on web).

  • “Add stop” chip — pressed: fill --brand-weak.

Keep hover effects behind @media (hover: hover) on web so touch devices don’t get sticky hover states, and map the pressed styles above to RN Pressable’s pressed state.

16. Empty, error & loading states

The three states every async surface must specify. They hang off the Trip status machine (ARCHITECTURE §5: idle | searching | routing | ready | error) and the DEFENSIVE contract (no silent failure; one success path + one error path per operation). Built entirely from existing tokens — no new tokens.

16.1 Loading — skeletons, not spinners

  • Prefer skeletons that mirror the silhouette of the incoming content (deal cards, nearby-store rows, grocery rows). The calm, card-driven look (§1) reads better as a settling layout than a spinning glyph.

  • Skeleton fill --surface-3; shimmer sweeps left→right to --border-strong on a --dur-slow loop with --ease. Match the element’s radius (§6). Reduced motion (§8): drop the sweep, show static --surface-3 blocks.

  • Anti-flash timing: show a skeleton only if the wait is likely > ~250ms; once shown, hold it ≥ 400ms so a fast resolve doesn’t flicker. Sub-250ms → show nothing.

  • Recompute-in-place (routing after a stop changes): don’t clear to skeleton. Keep the last RouteSummary / Worth-It visible at ~60% opacity with a 2px indeterminate --brand bar across the top of the panel; the map keeps the old route until the new one draws (--dur-slow). Never blank the map or float a full-screen spinner over it.

  • Persist is not a loading state: keep the editor rule (GROCERY_EDITOR §7) — no spinner, a subtle “Saved” tick.

  • Spinner is the exception, only where no silhouette is knowable (e.g. the “Open in Maps” hand-off): 18px, 2px stroke, arc in --brand, track --border; under reduced motion show a static ring + label instead.

16.2 Empty — two tiers, and never dishonest

  • Zero-state (a whole surface has no content — empty list, no nearby stores, no deals this week): a centered block ~max 320px — a 32px stroke icon in --text-3 (placeholder until the §14 illustration style lands), title body-lg/600 --text, one body --text-2 line saying why and what next, then one primary action (§7). Reserve display type (§5) for the first-run / marketing hero only, not routine empties.

  • Inline empty (an empty section inside a populated surface, e.g. an empty category): a single quiet row, body-sm in --text-3 (“Nothing here yet”). Matches GROCERY_EDITOR §7.

  • Partial ≠ empty (honesty rule). “3 of your items on sale here” (GROCERY_LIST §9) is a result, not an empty state — show the matches plainly; never dress a partial match as “nothing found.”

  • Geolocation denied is not an empty/error state (LOCATION §10): fall through to the manual address / postal path as a first-class input — no scolding.

  • Copy is warm, specific, actionable: “No deals near this postal code this week — try a wider search or another store,” not “No results.”

16.3 Error — one path, plain language, a way forward

Per DEFENSIVE (one clear success path and one error path; typed, validated results at every lib/ boundary):

  • Blocking error (the surface’s core op failed — OSRM code !== 'Ok', empty route, or missing geometry per DEFENSIVE, or a deals/stores fetch failure): an inline error block on the affected surface — never a modal, never a raw string/stack, and never a broken map (DEFENSIVE: surface as status: error, don’t render broken geometry). --danger icon + title body/600 --text + one body-sm --text-2 line naming the cause in plain terms + a secondary “Try again” button (§7) that re-runs the op. Retry is bounded — fixed count + backoff, never a loop (DEFENSIVE).

  • Transient / action error (a save, undo, or single request blipped): a --danger-accented snackbar (same family as the editor UndoSnackbar, §8), --danger-weak bg / --danger text + icon, auto-dismiss ~6s, with a “Retry” action where the op is safe to repeat.

  • Color discipline: errors use --danger / --danger-weak only — distinct from --cost amber (an honest debit, §4.2) and from the “Skip ✕” verdict (a real recommendation that merely shares --danger, not a failure).

  • Tone: name what happened + the next step; no blame, no error codes in the UI (log codes, don’t show them). e.g. “Couldn’t build a route between these stops. Try removing or changing the last one.”

  • Pair color with a glyph + word (§8): an error is never signalled by red alone.
